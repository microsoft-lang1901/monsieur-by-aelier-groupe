# MONSIEUR Tier 1 Ecommerce Mobile Platform Task List

This task list defines the work required to elevate MONSIEUR from a production-architected MVP into a full Tier 1 luxury ecommerce mobile application platform.

## Current Baseline

Completed locally:

- Catalogue-driven Expo React Native mobile app.
- Product, collection, material, and Fibre Passport generation.
- Editorial home, collections, search, wardrobe, account, product detail, and checkout screens.
- Local wardrobe, cart, account, order, and atelier request persistence.
- Stripe and Supabase integration boundaries.
- Production assets wired.
- Release gates for TypeScript, tokens, content rules, Supabase policies, accessibility, contrast, assets, deployment config, tests, and web export.
- CI workflow for verification.

Current limitation:

- The app is not yet a fully deployed Tier 1 ecommerce platform because production backend, payment, fulfilment, CMS, observability, native builds, store release, and physical-device QA remain incomplete.

## Stage 1: Production Infrastructure

Tasks:

- Create production Supabase project.
- Apply `supabase/schema.sql`.
- Verify all tables, indexes, constraints, and RLS policies.
- Deploy `supabase/functions/create-checkout-session`.
- Configure Supabase secrets:
  - `STRIPE_SECRET_KEY`
- Configure app environment:
  - `EXPO_PUBLIC_SUPABASE_URL`
  - `EXPO_PUBLIC_SUPABASE_ANON_KEY`
  - `EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY`
- Run `npm run validate:env`.
- Run `npm run release:production-check`.
- Create production Expo/EAS project with `npx eas init`.
- Commit the real EAS project id generated by Expo.

Acceptance:

- Supabase deployment is live.
- RLS is verified with test users.
- Edge function creates Stripe payment intents successfully.
- Production env validation passes.
- `npm run release:production-check` passes.

## Stage 2: Authentication And Client Identity

Tasks:

- Implement Supabase Auth in the mobile app.
- Replace `local-client` with authenticated user ids.
- Add session restore on app launch.
- Add sign-in/sign-out flows inside Account.
- Add secure profile persistence.
- Add account deletion request path.
- Add privacy-safe error states.

Acceptance:

- Client can authenticate on iOS, Android, and web preview.
- Wardrobe, orders, profile, and atelier requests are scoped to authenticated user.
- RLS blocks cross-user reads/writes.
- Session restore works after app restart.

## Stage 3: Commerce Core

Tasks:

- Replace mock/local checkout confirmation with real Stripe PaymentSheet flow.
- Support Apple Pay on iOS.
- Support Google Pay on Android.
- Add cart review screen or modal without adding a sixth tab.
- Add order creation after confirmed payment.
- Add payment failure handling.
- Add idempotency for checkout requests.
- Add order status lifecycle:
  - confirmed
  - preparing
  - dispatched
  - complete
  - cancelled
- Add refund/cancellation admin pathway.

Acceptance:

- Stripe test payments complete on physical iOS and Android devices.
- Apple Pay and Google Pay are verified on device.
- Orders are recorded only after payment confirmation.
- Failed payments do not create completed orders.

The platform may be presented as a complete Tier 1 ecommerce mobile application platform only when all of the following are true:

- Production backend deployed.
- Real authentication active.
- Real payment flow verified.
- Apple Pay and Google Pay verified.
- Inventory and fulfilment logic active.
- CMS connected.
- Product imagery complete.
- Observability active.
- Security and privacy checks complete.
- CI passing.
- Native iOS and Android QA complete.
- Store submission package complete.
- Luxury UX audit passed.

npx eas build --profile production --platform android
